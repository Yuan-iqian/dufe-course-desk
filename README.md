# 东财课历 0.14.0

电脑与手机客户端，包含全部课程作业汇总、按课表接续的签到提醒、校园公告。学校账号在官方页面登录；本程序不设置单独的账号密码。同课共享与原网页入口已停用。

## 开始使用

1. Windows 双击桌面的「东财课历」快捷方式，或安装目录中的 SignInReminder.exe。新版图标是蓝底日历与金色银杏叶。
2. 点击「登录学校」，在学校官方窗口输入学校账号、密码或验证码；完成后返回应用。程序会验证登录并同步课表和本学期全部作业。
3. 在「课堂签到」选择「跟随全部课程」，点击「开始监控」。程序会依照白果云课表检查每节课。校园通知的关注设置在「校园通知 → 我的关注」。
4. 登录过期时重新打开学校窗口。公告页的「退出账号」会退出学校登录、清空当前显示并停止此账号的提醒；已保存记录仍按账号保存在本机。
5. 点击右上角主题按钮旁的咖啡杯，可查看赞赏码及图片下方的 QQ 交流说明。

## 账号记忆

在学校官方窗口正常登录一次后，应用会自动记住本机的登录状态。下次完整退出再打开时，会先恢复记录并向学校确认；学校仍认可这次登录，就可以直接同步课程、作业和使用校园码。校园码窗口完成登录并返回应用后，也会重新确认课程登录。电脑、安卓和 iPhone 各自保存本机记录，不在设备之间传递账号。

登录记忆保存的是 Cookie（学校用来识别登录状态的记录）。主动选择「保存到本机」时，软件才会另存你填写的账号和密码。额外的登录副本由 Windows 系统加密、安卓系统密钥或 iPhone 钥匙串保护，只留在本机；学校页面自己的存储仍由系统浏览器组件管理。已有登录在新版首次运行时会尝试自动沿用，必要时再正常登录一次。安卓旧版系统网页组件不支持完整读取登录记录时，仍沿用原来的网页存储；可更新 Android System WebView（安卓应用内用于显示网页的组件）以使用完整记忆能力。

学校设定的过期时间不变；密码修改、学校撤销登录或要求验证码时，仍需在官方页面完成验证。正在填写账号的学校窗口不会被后台恢复流程刷新。在「校园通知」点击「退出账号」会同时清除学校网页登录和加密副本，下次打开需要重新登录。

Windows 已验证完整进程重启、加密恢复、过期与损坏记录、退出期间的旧请求。手机共享逻辑通过模拟原生接口验证；Android 安装包仍需真机确认，iPhone 工程需在 Mac 编译并实机验证。

## 一键填写学校账号

点主界面右上角的齿轮「本机账号设置」，输入学校账号和密码，再点「保存到本机」。需要重新认证时，点「打开学校并一键填写」，在学校官方页面核对后自行提交并完成验证。点「清除已保存账号」可以删除这份记录。登录状态与保存的账号是两份独立记录。

Windows 使用当前系统账号的加密保护，Android 使用设备密钥，iPhone 使用仅限本机的钥匙串。账号和密码只用于填写学校统一身份认证的官方表单。

## 我的校园码

在「今天」点击「我的校园码」。软件打开学校官方校园码页面，使用本机学校登录记录；学校要求重新认证时，在官方页面完成登录和验证。页面上的姓名与账号以学校实际显示为准，换人使用设备时先在「校园通知」退出学校账号，再登录自己的账号。

校园码由学校直接生成并维护，不把二维码保存为可重复使用的截图，不上传到公告服务。电脑和手机使用独立的校园码窗口，不占用课表与签到监控的学校页面。顶部可以刷新和返回应用；电脑休眠或手机从后台恢复后会重新打开官方入口。学校暂时连接失败时隐藏旧画面并提供重试。退出账号时关闭旧校园码窗口并清除学校登录记录。

已在 Windows 的学校官方页面确认登录后个人二维码图片能加载。桌面隔离窗口与退出、断网、恢复流程使用受控页面测试通过；Android/iPhone 仍需真机检查，校门设备能否识别需在现场验证。学校如要求额外权限、校内网络或重新登录，按官方页面提示操作。

## 功能与提醒范围

- 东财开场：完整启动时播放约 1.5 秒，依次呈现校门、樱花林与校园俯瞰。可点「跳过」进入首页。托盘或手机后台恢复时不重播。系统开启「减少动态效果」时使用短淡入。
- 显示主题：点击右上角「主题」或调色盘图标。可分别选择五种主题颜色和六张背景图片，图片会渐变融入整页底色。课表、表单和弹窗使用主题对应的实色底。应用会记住颜色与图片的组合。

- 课程表：每周课表默认显示本周，可用教学周选择框或上一周、下一周切换。总课表用相同的周一至周日布局展示整个学期，课程卡片标注实际有课的周次。

- 东财校园图：整页背景可选校门与之远楼、樱花林、校园俯瞰、银杏路、莘子园和东财雪景。校门为实景照片，其余为依据校园资料绘制的插画。首页点「换一景」独立切换顶部横幅。
- 界面动效：切换主页面时导航高亮会滑到当前页。校园背景在图片就绪后展开，连续点按可打断前一个过渡。系统开启「减少动态效果」时使用短淡入。
- 今天首页：优先显示正在进行的签到和今天截止的作业，随后展示当前与下一节课，以及未来 7 天的作业和校园待办。校园待办来自已确认期限且未标记完成的通知。
- 同步状态：课表和作业分别显示上次成功同步的时间，遇到登录过期或同步失败可从首页重新登录或重试。签到区显示正在检查的课次、上次成功检查签到的时间和下次检查倒计时。

- 作业：全部课程、待提交/待批改/已批改/逾期分类、搜索、排序、学校原文入口，运行时约每 5 分钟同步。
- 课堂练习：与签到同时按课次检查。首次检查该课次时已有的练习会显示在课堂活动里，新开始的练习会发出提醒。点提醒打开学校的练习列表。
- 签到：同步本周和下周的全部课程，从课前 10 分钟检查到课后 15 分钟。相邻课次时段重叠时会兼顾两节。支持 15/30/60 秒检查、提醒去重和手动指定课次。完成签到仍在学校官方页面操作。
- 公告：11 个学校公开来源，按来源、分类、日期筛选，搜索、正文摘录、原文、关注关键词、已读/完成状态、手工确认截止日期。
- Windows：关闭主窗口后继续在托盘运行；电脑关机、休眠或完全退出程序时停止检查。
- Android/iPhone：前台检查新消息；开始监控后将已同步、未提交作业的截止前 24 小时与 1 小时提醒登记到系统。最多安排最近 60 条，系统通知权限和节电设置可能影响送达。退出学校或暂停监控会取消这些已登记提醒。
- 手机不承诺锁屏后持续查询学校新签到、新作业和新公告。后台时学校的提交状态、延期或取消不能即时获知，应重新打开应用同步。
- 公告期限为从正文提取的候选日期，可手工确认；这一版没有公告截止时间系统推送。

## 数据与云端

学校登录凭据留在此设备的官方学校窗口，不上传到公告服务。个人公告关注、已读、完成与手工日期按学校账号保存在本机，各设备暂不自动同步；原网页账号的个人状态也未自动迁入。旧资料与旧数据库保留。

云端只采集公开公告。教务处和学生工作部目标每 15 分钟检查，其他来源每小时检查；每分钟最多处理一个来源或一篇正文，失败后逐步重试。手机、电脑约每分钟同步已有云端结果。原公网地址目前仅供客户端取公告，浏览器入口已停用。

## 开发与验证

桌面：Node.js 24（运行构建脚本的工具），npm ci，npm test，npm run test:ui，npm start。
手机：进入 mobile 目录，npm ci，npm run sync。Android 使用 Java 21 和 Android SDK 36；iPhone 需要在 Mac 上用 Xcode 编译。
桌面端运行 npm run package 生成 Windows 程序。手机端完成同步后，在 mobile 目录运行 npm run android 或 npm run ios 打开对应开发工具。

校园公告服务位于 cloudflare-sharing。进入该目录后运行 npm ci 和 npm run build。要在本机运行服务，先将 wrangler.example.json 复制成 wrangler.json，再运行 npm run db:local 和 npm run dev。如需部署到自己的账号，请在配置中填写自己的 D1 数据库标识，应用数据库迁移，并将 src/hosted-service.json 中的服务地址改为自己的地址。

原校园公告解析器的来源和许可保留在 src/vendor/zhicai，Bootstrap 与 Lucide 的许可随程序保留。
